# VEIL: Confidential Sealed-Bid Trading Primitive on Sui

## 1. Introduction

Public blockchains inherently struggle with privacy. For auctions and trading protocols, this lack of confidentiality leads to front-running, MEV (Maximal Extractable Value) sniping, and the inability to execute large block trades (OTC) without immense market impact. 

**VEIL** is a cryptographic sealed-bid primitive built on the Sui blockchain that solves this. It guarantees that an incoming bid or quote hides three critical pieces of information until the auction officially closes:
1. **Value:** The amount being bid.
2. **Existence:** The fact that a specific bid exists on-chain.
3. **Identity:** Who submitted the bid.

VEIL operates as a foundational engine that powers two distinct applications:
- **VEIL-Launch**: A fair, anti-snipe token launchpad using uniform-price clearing.
- **VEIL-OTC**: A sealed-quote RFQ dark pool allowing makers to set completely hidden reserve floors.

## 2. Cryptographic Architecture

VEIL achieves its confidentiality by orchestrating three cutting-edge technologies: **Seal**, **Walrus**, and **Sui Move**.

### 2.1 Encryption via Seal (Threshold IBE + Time-Lock)
When a user submits a bid, it is entirely encrypted on the client side. The encryption leverages **Seal**, a Threshold Identity-Based Encryption (IBE) protocol. The decryption identity is derived directly from the auction's unique ID and its closing timestamp. 

This creates a strict **time-lock**: the decryption keys cannot be mathematically generated by the Seal key servers until an on-chain policy (`seal_approve`) confirms that the current blockchain time has surpassed the auction's `closeTime`.

### 2.2 Decentralized Storage via Walrus
Storing large ciphertext blobs directly on-chain is expensive and scales poorly. Instead, the encrypted bid payload is uploaded to **Walrus**, a decentralized storage network tailored for the Sui ecosystem. The client receives a lightweight `blobId` in return.

### 2.3 On-Chain Commitments via Sui Move
With the data safely encrypted and stored off-chain, the client submits a transaction to the Sui smart contract containing only:
1. The Walrus `blobId` (pointing to the encrypted data).
2. A cryptographic hash (SHA-256) of the plaintext bid as a `commitment`.

Because the contract only sees a hash and a pointer, the blockchain state leaks zero information about the auction's demand curve while it is active.

## 3. The Settlement Flow & The Keeper

Once the auction's `closeTime` is reached, the state naturally transitions from `SEALED` to `REVEALING`. 

A specialized off-chain worker (the **Keeper Orchestrator**) automates the settlement:
1. **Fetch:** Downloads all encrypted bid blobs from Walrus using their `blobId`s.
2. **Unseal:** Requests decryption from the Seal threshold network by submitting a Sui transaction calling `seal_approve`, proving the auction has closed.
3. **Shape & Validate:** Decrypts the plaintexts and organizes them into sorted arrays (price, quantity, nonce).
4. **Settle:** Submits the plaintext arrays back to the Sui smart contract. 
5. **Verify:** The smart contract re-hashes every plaintext bid on the fly. If the hash matches the original `commitment` submitted during the auction, the bid is valid. If not, the transaction aborts.

### 3.1 Data API Integration (Tatum)
As part of the settlement execution, the Keeper queries the **Tatum Exchange Rate API** to fetch the real-time SUI/USD market price. It computes the mark-to-market fiat equivalent of the auction's clearing price.

### 3.2 Archive-on-Settle
Once settlement is successful, an `ArchiveRecord` is constructed—containing the winner, the clearing price, and the total bid count. This record is JSON-encoded and permanently pushed to Walrus, ensuring a decentralized, immutable trade history without bloating on-chain state.

## 4. Smart Contract Engine

The core Move contracts (`move/veil/sources/`) handle all financial logic with mathematically rigorous safety guarantees.

- **`settlement.move`**: A pure, stateless clearing engine. It implements `clear` for single-winner auctions (first-price and Vickrey/second-price) and `uniform_clear` for multi-unit token launches. It walks the demand curve, fills strictly-above bids in full, and calculates pro-rata allocations for bids precisely at the marginal clearing price, all utilizing overflow-safe `u128` arithmetic.
- **`auction.move`**: The base sealed-bid state machine managing deposits, escrow, time locks, and commitment verification.
- **`veil_launch.move`**: Leverages the uniform-price clearing function to execute fair token distributions where all winners pay the exact same marginal price, completely eliminating MEV sniping advantages.
- **`veil_otc.move`**: An RFQ module where the maker's reserve floor is also committed as a hidden SHA-256 hash (`reserve_commitment`), ensuring that market makers cannot be front-run or squeezed by counterparties reverse-engineering their floors.

## 5. Conclusion

VEIL transforms public blockchain trading from a transparent, adversarial environment into a secure, sealed ecosystem. By aggressively pushing data to Walrus and leveraging Seal's cryptographic time-locks, VEIL proves that high-stakes decentralized finance can be both fully trustless and completely private.
